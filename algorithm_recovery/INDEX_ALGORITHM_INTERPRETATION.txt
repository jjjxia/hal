1. 两份固件共有的三路环形缓存结构

  所有 Mxx 表示 DANA_module_xx。下标 [i] 是保存程序的位坐标；对于未决
  位序的控制字，它不额外断言该坐标是某个源程序整数的第 i 位。

                         手柄 controller                 头显 hmd
  wp（9 位）             M41                             M42
  rp（9 位）             M42                             M43
  RAM 三路 M0/M1/M2      g11023/g11024/g11025             g11099/g11100/g11101
  写入数据 D0/D1/D2      M18/M15/M20（各 16 位）           M20/M10/M19（各 16 位）
  WR                     M108[6] && M96[8]                M109[5] && M95[9]
  RR                     M173 && !M69[0]                  M180 && !M68[1]
  wp 更新 guard          c_b1928                         c_b6306
  rp 更新 guard          c_b2278                         c_b6089
  异步复位               c_b1756                         c_b1777
  时钟                   c_b3（physical pad 3）          c_b3（physical pad 3）

  wp/rp 的数值位序在两份 state_schema.json 中都为已知。低 8 位是 RAM
  地址，第 9 位参与绕回比较。三路都为 256 x 16，地址、时钟和写使能相同，
  MASK=0，RE=RCLKE=WE=1；因此可视为每个地址保存三个 16 位分量。
  这里只约定了元组顺序，没有恢复外部协议中一个 48 位整数的字节序。
  三路 RAM 内容 INIT 均为零，读锁存器初值未知；运行时保留该区别。

  物理位绑定（各数组从最低位到最高位）：

         rp=[549,551,553,555,557,559,561,563,2287]。
    头显 wp=[1503,1505,1507,1509,1511,1513,1515,1517,6315]；

    schema：controller/state_machine/state_schema.json:23321,23351；
            hmd/state_machine/state_schema.json:26010,26040
    （以上 schema 路径共同前缀为 build/guarded_state_v1/）。

  以下是两个程序共同支持的局部状态递推（同事件均使用旧状态）：
    empty = (wp == rp);
    full  = ((wp ^ rp) == 0x100);              // 9 位指针
    on rising(clk):
      read0,read1,read2 = M0[rp&255],M1[rp&255],M2[rp&255];
      if WR: M0[wp&255],M1[wp&255],M2[wp&255] = D0,D1,D2;
    when reset is high: wp,rp = 0,0;          // RAM 本身不随此复位清空
    on rising(clk) when reset is low:
      if WR && !full:  wp = (wp+1) & 511;
      if RR && !empty: rp = (rp+1) & 511;
    otherwise retain the corresponding state; // RAM 同事件先读旧值再写

  关键限制：RAM 的实际写使能是 WR，而不是 WR && !full。满状态会阻止
  wp 前进，却不直接阻止该地址写入。是否由上游保证满时没有 WR、是否允许
  覆盖或另有协议含义，当前尚未证明。不能把程序改写成“满时忽略写入”，
  也不能根据指针形状直接声称已经恢复了安全 FIFO、无丢失队列或容量保证。

2. 写入缓存的数据从哪里来

  手柄：M33 --[c_b3739]--> M30 --[各自使能]--> M18/M15/M20 --> 三路 RAM。

  这正是当前从可执行行为继续走到高层算法描述的具体缺口之一。
