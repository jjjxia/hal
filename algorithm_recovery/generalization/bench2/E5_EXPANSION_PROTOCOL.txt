E5 expanded benchmark evaluation -- protocol, written 2026-11-03 BEFORE any E5 recovery run
=========================================================================================
Requested by the user on 2026-11-03 ("多找点benchmark ... 学 Sisco 的 Fungible Memory PLDI26 和 Loop Rerolling
两篇找 benchmark 的思路以及 metric"). Method borrowed from:
  * Sisco et al., Loop Rerolling for Hardware Decompilation (PLDI 2023): modules taken from a standard component
    library (BaseJump STL) "without regard to their original SystemVerilog code containing loops"; every module in
    small/medium/large parameterizations; found/expected loops, phase times, gzip artifact compaction, failures
    (timeouts) reported.
  * Sisco et al., Fungible Memories (PLDI 2026): micro-benchmarks from open-source suites (BaseJump STL, OPDB),
    Yosys netlists with ABC, ground truth from the source (expected memory dimensions and ports), comparison with
    baseline inference tools, larger case studies, per-phase timing.

E5.C Synthetic folding with known ground truth (Theorem 7)
------------------------------------------------------------
Generator (written and frozen before scoring): random single-rate DFGs (8-bit add/sub/xor/and/constant-multiply
nodes, 6-16 nodes, sample delays 0-2 on edges, inputs and outputs), folded with a registered fixed-binding schedule
in the style of Parhi's folding: N in {2, 4, 8}, random unit binding and slot order, every node result written to
its bound register, operands routed through explicit delay registers. 8 graphs x 3 folding factors = 24 designs,
plus two out-of-class controls per graph family: (i) one unregistered chained edge (predicted: two DFG nodes merge
into one event), (ii) binding rotating between transactions (predicted: graph period = 2 transactions, program
refused). Each design goes through the full gate-level pipeline. Scorer: the generator's (register, slot) -> DFG node
map; a recovered event graph, with identity moves collapsed, is "exact" iff it is isomorphic to the DFG with every
operand's producer and sample delay equal. Reported: exact designs / total, per-edge producer and delay accuracy.

Metrics (all E5 designs where applicable)
------------------------------------------
M1 outcome: certified (origin/period, goals, time) / refused by the pipeline (stage and reason) / out of budget /
   tool failure.
M2 structure vs RTL oracle: bench2/c2_oracle.py with the E2.1 definitions, unchanged (write-event recall and
   precision, producer exact match, delay accuracy, multi-role registers).
M3 found / expected (Loop Rerolling style): expected time loops and trip counts (round/iteration counters in the
   source) and expected table instances (S-box/ROM in the source) are written in E5_EXPECTED.txt BEFORE the run;
   found = roll-up loops and lifted tables.
M4 correctness: end-to-end check (c3/close_chain.py) for flat/rolled/lifted programs; held-out trace comparison
   (decompile validation); documented algorithm on 2,000 fresh inputs where a reference model exists (written before
   the run; missing references are reported as such).
M5 compaction (Loop Rerolling): gzip -9 bytes of the final program relative to the flat program (same representation
   before and after roll-up/lifting, as Loop Rerolling compares rerolled and non-rerolled code), netlist for scale; lines
   flat / rolled / lifted.
M6 time and peak memory per stage.
M7 folded RTL: c3/emit_rtl.py cycle-by-cycle validation on the training and fresh-data traces.
Reporting: every E5 design appears in the results, including failures; numbers are not tuned between designs.

Amendment 1 (2026-11-03, after the first E5.C calibration design e5c_s1_n4, before scoring the E5.C set):
 (a) Generator: DFGs in which some node is constant over all runs from the zero reset state (e.g. a multiplicative
     self-recursion from 0, or an AND with a zero-initialised history) are rejected and regenerated (64 random samples
     must give >= 2 values per node). Such nodes are certified constants, so they carry no data edges; the calibration
     design had three (n8, n9, n12) and showed exactly that. The recovery pipeline is unchanged.
 (b) Scorer granularity: DANA groups registers with identical enables into one word (e.g. the four copy registers
     written at slot N-1). As in the E2.1 oracle, recovered events are mapped to RTL registers at bit level: each
     register's slice of a word event is scored separately; a register split across words or a word bit without an
     RTL register name remains a grouping failure. Merged words are reported (words_merging_registers).
 (c) Scorer fixes found while scoring the first two designs, applied before scoring the rest (recovery unchanged):
     memoised copy-chain expansion (exponential recursion through merged copy words); graph-coordinate delays are
     converted to transaction coordinates with the retiming of c3/decompile.py (delay + rho(phase) - rho(source phase),
     Theorem 5), which the first version omitted (all delays across the graph origin were off by one). The two injected
     graph mutations (one delay, one producer phase) are still rejected after both fixes.
 (d) Scorer, after the E5.C batch (recovery unchanged): edges are compared on semantic dependence -- an operand counts
     if changing its value alone can change the node's value (z3) -- because e5c_s3_n4_rotate's node n11 keeps a
     syntactic read of n12 that does not affect its proved-equal function. Syntactic edge counts are reported as well
     (nodes_edges_syntactic_exact). All E5.C designs were rescored; the injected mutations are still rejected.
 (e) Chain-control prediction, corrected after the batch (recovery and generator unchanged): when the chained producer u
     has no other reader and is not an output, the generator's allocation gives u and v the same register in the same
     slot, so u's write is dead and u has no event; the predicted structure is v with u's operation inlined and no node
     for u. The scorer now predicts this (dead_chained_producer); it applied to e5c_s2_n4_chain and e5c_s3_n4_chain.
     Refinement of (e) on the next design: the dead write arises whenever another node (v or any other) shares u's
     register in u's slot (e5c_s3_n4_chain: n14 and n5 both in r5 at slot 2); the condition now covers any such node.
 (f) Budget enforcement (2026-11-03, before any E5.A/B result): the frozen run_bench2.sh sets its own `ulimit -v 16 GiB`,
     so the declared 6 GiB stage budget was not enforced on its stages; a first siphash_c1d3 run reached 4.9 GB RSS in
     the groups stage after 23 min and was stopped (kept as bench2_e5/siphash_c1d3.uncapped_partial, no result).
     e5_run_case.sh now runs prepare and run_bench2.sh under an outer hard 6 GiB limit; stages exceeding it fail and
     are reported as over budget.
