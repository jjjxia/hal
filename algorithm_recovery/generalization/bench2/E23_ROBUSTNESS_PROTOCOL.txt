Algorithm: PandA-bambu examples/arf_res_sharing/module.c (commit c2ba6936), Bambu 2024.10
(official AppImage from release.bambuhls.eu, 1,405,510,848 bytes), same command as bambu_arf:
  bambu --top-fname=arf --generate-interface=INFER -v2 module.c constraints_ui_mult<N>.xml
Variants: N = 1 (the frozen held-out bambu_arf), 2, 4 (tech_constraints ui_mult_expr_FU n=N).
Synthesis: Yosys 0.33 synth_ice40 -nobram (as bambu_arf). Protocol: as bambu_arf
(reset 2 cycles, start_port=1 at cycle 0, period 16 cycles, data held), provided the
generated design finishes within 16 cycles; otherwise the period is the smallest multiple
of 4 cycles that covers done_port, fixed from an RTL simulation before recovery.
Pipeline: prepare_bench2 -> run_bench2.sh stages -> graph -> c3/decompile.py.
Reported per variant (no tuning between variants): certificate (origin, period), graph
nodes and excluded words, multi-role registers (storage_reuse), proven additions, fitted
multiplications (tested, proof status), program lines, held-out and 2000-input reference
checks against module.c. Robustness holds if every variant passes the reference check and
the counts of recovered operations per transaction agree up to the expected reuse.
