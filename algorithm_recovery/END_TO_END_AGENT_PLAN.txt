End-to-end firmware -> readable executable C++: execution plan
Owner: Codex; authorized by user 2026-11-01. Ordinary engineering task, no
research goal/loop. Work in the independent HAL checkout, commit coherent steps.

Objective
  Native HAL + our C++ extension, with no per-design semantic hints, should
  recover as much executable behavior and readable structure as the input
  supports. Produce actual synthesized C++, not merely equations in JSON or a
  handwritten algorithm description. Preserve original physical identities,
  widths, bit order, clocks/resets, RAM, unknowns and all proof boundaries.

Architectural decision
  A trace-guided equation is a specialization of the circuit's transition
  relation under recorded control assumptions. A repeated trace schedule is one
  execution schema, not the complete control automaton. Retain guards and state
  dependencies, merge equivalent updates, and obtain unobserved behavior from
  the original symbolic circuit when supported. Do not manufacture missing
  branches or require the whole-device observed-period LCM to discover every
  useful transition. Keep raw, exact fallback expressions where lifting fails.

Milestones (execute, validate, commit; do not stop at this plan)

1. Synthesize executable arithmetic into the existing native C++ exporter.
   - Consume FIT_PROVED models and proved routing coordinate permutations.
   - Emit direct integer arithmetic with explicit signedness, dyadic floor,
     wrap and permutation semantics. Keep unlifted exact functions as fallback.
   - Decode the saved generated function bytes and prove them against the raw
     graph function; also compile and replay, including negative/wrap cases.
   - Enable it in the actual analyze pipeline. Provide a native re-export path
     for the existing seven validated programs without re-running HAL MI.

2. Recover executable structure from the periodic graph.
   - Normalize source bindings by time lag and state identity; consolidate
     repeated word updates with identical operation, guards and dependencies.
   - Emit explicit state updates, phase conditions and repeated execution in
     C++ with original word names. Preserve simultaneous-event and RAM ordering.
   - Validate expansion of the structured schedule against every original node,
     source, phase, history entry and RAM operation before adopting it.
   - Retain a complete traceable mapping and report genuinely unresolved pieces.

3. Recover guarded state transitions beyond a single instantiated schedule.
   - Persist conditional SSE variants as transitions, including physical guards,
     FF write/reset semantics, dependencies and the existing equivalence proofs.
   - Merge identical transitions across observations and profiles. Preserve
     data-dependent guards in emitted control flow, rather than hard-code their
     trace values or equate schedule phase with the original FSM state.
   - Evaluate a native event/state backend with symbolic original-circuit
     fallback for uncovered guards/aperiodic groups. Use HAL SSE for extraction
     and the independent original interpreter for checking, not a hand-written
     recovery substitute. Explicitly retain unsupported/X-state cases.
   - Apply it to the HMD pattern gap; a large LCM must not silently erase
     recoverable local state transitions.

4. End-to-end validation and delivery.
   - Meaningful regression cases: signed arithmetic, wrap, nontrivial routing,
     delay across frames, branch guards, simultaneous clocks, RAM read-before-
     write, unknown initialization, and malformed/mismatched artifact rejection.
   - Compile and execute both firmware outputs against original-gate reference
     observations with unchanged known/unknown-bit accounting and withheld data.
   - Show the actual highest-level generated source and exact invocation paths;
     distinguish demonstrated function from speculative product/protocol roles.
   - Record coverage and remaining limitations in one current record; selective
     add/commit code/configuration/compact results, no build artifacts or push.

Resource and execution discipline
  Existing all-type HAL expansion remains one serial queue: controller then
  HMD; each case 180 minutes and 16 GiB per-process virtual address space.
  Do not start another heavy recovery case concurrently or modify bytes of
  libraries mapped by its running process. Development builds use one worker
  and separate/preserved output inodes as needed. Never overwrite validated
  artifacts or change a proof contract merely to obtain a passing result.

Milestone 3 implementation decision (2026-11-01, not implemented yet)
  Use a distinct guarded event-transition representation, not a fabricated
  observed period=1. Reuse the proved expression/schedule emitter as a one-event
  execution backend only with an explicit execution-kind contract. Include all
  DANA FF groups (including unknown numeric order and nonperiodic/no-write groups)
  as physical storage. Every old FF value is state, not a trace-fed cut input.

  Extract unconditional word D/control/observable cones with HAL SSE's native
  vector<Net*> API. Check against OriginalCircuit's independent LUT/carry
  interpretation. Retain trace-guided specializations as guarded alternatives,
  with the unconditional HAL expression as exact fallback for unobserved guards.
  Construct each FF's enable, edge, synchronous/asynchronous reset/set and hold
  semantics from its actual primitive/pins; mixed word controls become masked
  bit updates rather than exclusions. Pack physical FF/RAM leaves into existing
  storage words without inventing numeric order. Fit and prove readable
  arithmetic on the recovered expressions; unsupported fits stay exact.

  An event runner should calculate clock edges from symbolic control functions
  on old/new snapshots, compute all FF/RAM updates from one pre-update snapshot,
  and commit them together. Derived clocks and FF-dependent asynchronous resets
  require delta-event settling, not a silent primary-clock-only assumption.
  Stop with explicit nonquiescence if a bounded settling loop does not stabilize.
  RAM uses existing extracted mode-0 INIT/ports and read-before-write semantics.
  Unknown initial $dff/IO bits and RAM read latches must remain explicit choices;
  do not claim a complete four-state model from the current two-state runtime.

  Input/output closure includes physical pad inputs and observable pad drives.
  OriginalCircuit intentionally omits pad $mux drivers (A=z); export their B/S
  as output data/drive-enable via HAL instead of reading a driven pad as an
  internal oracle. Treat resolved inout reads as the hardware environment input.
  Confirm actual clocks/reset support before picking any simpler event backend.

  Implementation references:
    observations.h: OriginalFF / OriginalCircuit physical pins, support/function
    observations.cpp: FF regex and Yosys primitive update semantics
    guided.cpp: physical HAL mapping, combinational bitmap, normalized SSE,
      conditional variant proof receipts and unconditional RAM-port extraction
    sequential_symbolic_execution.h: get_word_values_at_z3(vector<vector<Net*>>)
    /usr/share/yosys/ice40/cells_sim.v: SB_DFF_INIT=0; $dff IO initialization differs
  Do not implement a second hand-written recovery interpreter in place of HAL.
  Reference gate interpretation remains the checking side of the pipeline.

  Preferred event-backend split: emit a proved combinational control/observable
  program (clocks, enable/reset/set and pad data/drive-enable) plus a proved data
  program (unconditional D, guarded trace variants, and unconditional RAM ports).
  Their FF/RAM input words are internal inputs wired from the event driver's own
  current state, not exposed trace-fed boundaries. Generate explicit C++ FF
  control branches in the driver; select a guarded specialized D when applicable,
  otherwise use full HAL D. This keeps arithmetic visible without trying to fit
  an entire muxed next-state word to one affine model. All data/control/port
  functions see one old-state snapshot per delta; update all FFs/RAM together.
  Emit an explicit execution_kind for combinational/event programs; no observed
  period assertion may be inferred from a one-step code-generation frame.
  Existing primitive/runtime semantics need differential Yosys/Icarus tests;
  an end-to-end artifact must report these trusted parts separately from
  universal function equivalence. Do not silently reduce output observations.
